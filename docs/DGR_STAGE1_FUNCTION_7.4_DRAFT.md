### Block 0 cross-check against 7.1/7.2/7.3 — mostly shared, but NOT verbatim-identical this time

Function 7.3's draft stated Block 0 was "verbatim identical in wording and
count" across 7.1/7.2/7.3, confirmed three times. **This pass adds a fourth
comparison and finds the pattern breaks for Function 7.4** — the first
genuine exception found in this program:

- **0.1 (all four items), 0.3.1, 0.3.3, 0.4.1–0.4.3, and 0.6.1–0.6.2 are
  verbatim identical** in wording to 7.1/7.2/7.3's own Block 0, confirmed by
  direct text comparison against TABLEAU 7.1.A (PDF p.21, printed p.21) —
  same `0.3.2`-numbering-gap pattern also holds (the table jumps 0.3.1 →
  0.3.3 for 7.4 too, exactly as for 7.1/7.2/7.3).
- **0.2.1 and 0.2.2 have genuinely different wording for 7.4**:
  7.1/7.2/7.3 all read "0.2.1 Développer un flair pour les marchandises
  dangereuses **interdites**" / "0.2.2 Reconnaître **des/les** marchandises
  dangereuses potentiellement **cachées**." Function 7.4's table instead
  reads "0.2.1 Développer un flair pour les marchandises dangereuses
  **cachées**" / "0.2.2 Reconnaître les marchandises **potentiellement
  dangereuses**" (dropping "dangereuses" from the middle and "cachées" from
  the end, and moving the hidden-goods concept from 0.2.2 into 0.2.1
  instead). This is a genuine, function-specific IATA wording variation —
  sensible for this function, since 7.4's personnel physically handle
  packages without seeing shipping documents, so a "flair for *hidden* DG"
  is their primary 0.2.1 skill, while 7.1/7.2/7.3's personnel (who do see
  documents) need a flair for *prohibited* DG at that same table position.
  (A quick scan of the same document's tables for Functions 7.5–7.9 shows
  further small wording variations at this same 0.2.1/0.2.2 position across
  functions — this appears to be a genuine feature of IATA's own source
  table, adapting the wording per function's actual work, not an extraction
  or transcription artifact.)
- **0.5.3 "Déterminer les documents exigés" is present in 7.1/7.2/7.3's
  Block 0 but is completely absent from Function 7.4's Block 0** — confirmed
  by direct image inspection of TABLEAU 7.4.A (0.5 jumps straight from 0.5.2
  to 0.6). This is the first time in this program that Block 0's *leaf count*
  itself differs (16 for 7.4, vs. the uniform 17 already seen three times for
  7.1/7.2/7.3) — again a sensible, function-specific omission: warehouse/ramp
  handling personnel do not determine what shipping documents are required
  (that is the acceptance function's job, Functions 7.2/7.3), so IATA's own
  table does not ask this function to be trained on it.

**Conclusion for whoever works on Functions 7.5–7.10 next: do not assume
Block 0 is a frozen, always-verbatim, always-17-item block.** It is mostly
shared but has real, source-confirmed, function-specific variation. Check
each remaining function's own Block 0 against the source table directly
rather than copying forward the "verbatim identical" finding from 7.1/7.2/7.3.

### Numbering gaps explained (not just observed)

- **0.3.2 is skipped** (table jumps 0.3.1 → 0.3.3) — same pattern as
  7.1/7.2/7.3. This document's Function 7.5/7.6 tables show `0.3.2`
  *is* used elsewhere ("Comprendre les responsabilités des passagers"), so
  this item exists in IATA's numbering scheme generally but is not assigned
  to Function 7.4 (nor to 7.1/7.2/7.3).
- **Block 6 skips "6.2"** (the table goes straight from 6.1 "Charger
  l'aéronef" to 6.3 "Décharger l'aéronef"). Checked directly in the same
  source document: `6.2 "Gérer les marchandises dangereuses avant et pendant
  le vol"` (with leaves 6.2.1–6.2.5: handling non-permitted DG in baggage,
  interpreting the NOTOC in-flight, applying emergency procedures, informing
  flight-ops/dispatch, informing emergency services) **is used by a
  different function's table** later in the same document (an in-flight
  cockpit/cabin-facing function, not 7.4's warehouse/ramp/loading role) —
  confirming this is a real, by-design gap in IATA's own numbering, not an
  extraction error.
