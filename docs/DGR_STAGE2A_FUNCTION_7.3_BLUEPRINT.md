## What "count" and "sample" mean here

- **Count** — the provisional CEILING size of the source-supported item pool
  for that leaf sub-task: the number of genuinely distinct, non-duplicate
  questions the cited slide/exam/checklist evidence can currently support,
  once drafted and Tier A–gated. It is a ceiling to draft *up to*, not a
  quota that must be filled — if per-item drafting later finds thinner
  support than estimated here, the smaller real yield wins, exactly as the
  standing rule requires.
- **Sample** — the number of items from that sub-task's pool that a single
  live exam sitting would typically draw, for future randomized-exam
  configuration. This is illustrative sizing for platform configuration, not
  itself a scored decision.
- Evidence citations below point back to the specific slide ranges, exam
  question numbers, or checklist item numbers already traced and
  independently re-verified in the cross-validation pass — no count here is
  invented without a pointer to that evidence.

   book.** However, the practice book would normally have served as a

   Block 3 items are actually drafted, they require an extra layer of
   qualified-instructor scrutiny precisely because there is no
   practice-book-derived alternate source to cross-check wording, numeric
   values, or distractors against — this is a standing instruction for
   whoever performs that drafting pass, not merely a note for this
   document.** If the genuine Function 7.3 practice book is later located,
   Block 3's pool ceilings below should be revisited (very likely upward,
   given the pattern already seen: KOST practice books in this program
   provide additional worked scenarios beyond what the course slides alone
   show).

   only.** Independently confirmed in the cross-validated Stage 1 pass:
   the course states an employer procedure must exist and staff must be

   The bank may test that personnel must know/follow the employer's
   procedure; it must never invent employer-specific procedure content. This
   mirrors the same restriction already recorded for Functions 7.1/7.2, but
   is applied here on the strength of Function 7.3's own independently
   confirmed thin evidence for this sub-task, not by assumption.

   now confirmed a third time across three functions' worth of KOST

   7.1/7.2 can ever support genuinely separate item pools from this KOST
   material — is made explicitly **for this function only**: yes, keep them
   as two separate official leaf sub-tasks (IATA's own table lists them

   obligation** (who reports, to whom, within what framework) rather than
   inventing an accident/incident conceptual distinction the KOST source
   itself does not draw. A future Tier A pass against the current 67th
   Edition text may find a genuine regulatory accident/incident definition

   thin.
4. **3.1.4 and 3.2.5 share their underlying worked examples** (the same

5. **0.4.2 (packing-group general principles, ★) vs. 3.2.3 (verify packaging

   sub-tasks' ceilings simultaneously. 0.4.2's own pool is kept to the

6. **Course baseline is the DGR 66th Edition, not the current 67th
   Edition/Addendum 1.** Every regulatory paragraph, table, and checklist
